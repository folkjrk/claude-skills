# Go Modularization Protocol (GMP) v2

Two repositories:

| Repo | Holds | Imports |
|---|---|---|
| **goutil** (separate git repo, own semver tags) | Reusable infra: `response`, `web`, `validation`, `logger`, `redisdb`, `envx`, later `postgresql`/`mongodb`/`httpclient` | stdlib + third-party only, **never** a service repo |
| **service repo** (e.g. `dpp`) | One product: config, wiring, routes, handlers, services, repositories, models | goutil + third-party |

Before scaffolding, read the goutil module path and version from the user's
`go.mod` or ask once; templates write it as `{{UTIL}}` (e.g. `github.com/acme/goutil`).
If goutil does not exist yet, keep the packages under `internal/util/` but write them
to the **goutil contract** below so they can be moved out without edits.

## Core Mandate: Dependencies Point Inward

```text
Handler (Fiber)  →  Service  →  Repository  →  DB / Redis / External API
```

Each layer depends only on the **interface** of the layer below. Concrete types are
constructed in exactly one place, `internal/app/<binary>/app.go`, and passed down
through constructors and `route.Deps`.

## Service Repo Structure

```text
cmd/<binary>/main.go                 # 🚪 ENTRY: swag general annotations + `if err := <bin>.Run(); err != nil { os.Exit(1) }`
internal/
├── app/<binary>/
│   ├── app.go                       # 🔌 WIRING: config → logger → infra (defer Close) → repo → svc → route.New(Deps) → listen/shutdown
│   ├── docs/                        # 📄 GENERATED by `make swag` — never edit
│   ├── route/route.go               # 🗺️ ROUTES: Deps struct, fiber.New(ErrorHandler), global mw, public/private groups
│   ├── route/route_test.go          # 🧪 app.Test against New(testDeps())
│   ├── middleware/middleware.go     # 🛡️ RequestID / AccessLog / Recovery / Auth for this binary
│   ├── handler/<resource>_handler.go# 🌐 HTTP: bind → svc → .JSON(c)
│   └── service/<resource>svc/
│       ├── <resource>_svc.go        # 📜 CONTRACT: interface + Req/Res structs
│       ├── <resource>_svc_impl.go   # 🧠 LOGIC
│       └── <resource>_svc_test.go   # 🧪 table-driven, mocked repo
├── repository/<resource>repo/
│   ├── <resource>_repo.go           # 📜 CONTRACT: interface
│   ├── <resource>_repo_impl.go      # 🗄️ DATA: queries only
│   └── <resource>_repo_mock.go      # 🎭 testify/mock
├── data/orm/<resource>.go           # 🧱 DB models (never serialized to clients)
├── domain/errors.go                 # ⚠️ sentinels: ErrNotFound, ErrAlreadyExists, ...
├── meta/                            # ⚙️ error_codes.go, locals.go, cache keys, TTLs, permission keys
└── config/config.go                 # 🔧 typed Config, Load() (only place reading env), Validate()
docs/                                # 📚 human specs (DESIGN_SPECS.md, ...) — source of truth for the API contract
Makefile  Dockerfile  docker-compose.yml  .env.example  .gitignore  .golangci.yml
```

- Service shared by several binaries → `internal/service/<area>svc/`.
- **No** `internal/util/` in the service repo once goutil exists. Project-only helpers
  go next to their single user; a helper needed by a second service repo moves to goutil.
- **No** aggregate `repository.Repository` struct or `repository.Init()`: each repo
  is its own package, constructed in `app.go`. One-time setup (indexes, migrations) is
  an explicit call in `app.go` that returns an error.

## goutil Contract

Every goutil package must satisfy all of these, because it is consumed by many repos:

1. **No app imports, no global config.** Never call `config.GetConfig()`; take an
   `Options` struct or explicit params. Env parsing helpers live in `envx`
   (`envx.String/Int/Bool/Duration/StringSlice(key, def)`), used only by a repo's `config` package.
2. **Constructors return values + error, no `sync.Once` singletons:**
   `redisdb.New(ctx, redisdb.Options{...}) (Client, error)` with `Close() error`;
   `validation.New() Validator`; `logger.New(logger.Options{Level, Format}) *slog.Logger`.
3. **ctx first on every I/O method** — no `context.Background()` inside the library.
4. **Interfaces for anything a service mocks** (`redisdb.Cache`, `validation.Validator`),
   plus an in-memory implementation for tests (`redisdb.NewMemory()`).
5. **No logging of payloads** — never log response `data`, request bodies, tokens, PII.
6. Tests in goutil itself; `go test -race ./...` green before tagging a release.

Expected packages and surface:

| Package | Surface |
|---|---|
| `response` | `Response[T]` envelope, `OK/Created/Accepted`, `BadRequest/ValidationFailed/Unauthorized/Forbidden/NotFound/Conflict/Internal`, `(r) JSON(c fiber.Ctx) error`, `ErrorHandler(c, err)` for `fiber.Config` |
| `web` | `HTTPHandler{ Init(fiber.Router) }`, `Register(router, ...HTTPHandler)` |
| `validation` | `Validator{ Check(any) []response.Detail }`; field names from `json` → `uri` → `query` tag |
| `logger` | `New(Options) *slog.Logger` (JSON default, TEXT option), error attr with stack trace |
| `redisdb` | `Cache{ Get/Set/Delete/DeletePrefix(ctx, ...) }`, `New`, `NewMemory`, `Close`, fiber `Storage` adapter |
| `envx` | typed env getters with defaults |

## Response Envelope

The API spec in `docs/` wins. Default (matches DESIGN_SPECS §1.1/§1.2):

```json
{ "success": true,  "message": "OK", "data": { } }
{ "success": false, "message": "Validation failed",
  "error": { "code": "VALIDATION_ERROR", "details": [ { "field": "email", "reason": "email must be email format" } ] } }
```

- HTTP status is the status line, not a body field. Error `code` constants live in
  `meta/error_codes.go` (`BAD_REQUEST`, `VALIDATION_ERROR`, `UNAUTHORIZED`, `FORBIDDEN`,
  `NOT_FOUND`, `CONFLICT`, `PAYLOAD_TOO_LARGE`, `INTERNAL_ERROR`, plus domain codes).
- The internal cause is a non-serialized field, put in `c.Locals(meta.LocalErr)` for the access log.
- 5xx `message` is always generic; never echo `err.Error()` to clients.
- `fiber.Config{ErrorHandler: response.ErrorHandler}` is mandatory, so 404/405,
  body-limit and recovered panics all return the same envelope.

## Layer Guidelines

### 1. Naming
- Files `snake_case.go`; packages lowercase; service packages end `svc` (`ticketsvc`),
  repository packages end `repo` (`ticketrepo`).
- Constructors `New(...)` return the **interface**: `func New(repo ticketrepo.Repo, cache redisdb.Cache, v validation.Validator) Svc`.
- A resource with ≤ 2 trivial methods may keep interface and impl in one file.

### 2. Handler (`handler/`)
- Implements `web.HTTPHandler`; registers its own routes in `Init`.
- Only: bind → `h.svc.X(c.Context(), req)` → `.JSON(c)`. Fiber v3 binding:
  `c.Bind().URI(&req)`, `c.Bind().Query(&req)`, `c.Bind().Body(&req)`.
- Bind failure → `response.BadRequest[any]("invalid request").JSON(c)`.
- Swag annotations on every handler method (`@summary @tags @id @param @success @failure @Router`).
- **Forbidden:** business rules, `if` on domain state, repo/DB/Redis access, building error messages.

```go
func (h *ticketHandler) Get(c fiber.Ctx) error {
	var req ticketsvc.GetReq
	if err := c.Bind().URI(&req); err != nil {
		return response.BadRequest[any]("invalid request").JSON(c)
	}
	return h.svc.Get(c.Context(), req).JSON(c)
}
```

### 3. Service (`service/`)
- Validate first: `if d := s.v.Check(req); len(d) > 0 { return response.ValidationFailed[T](d) }`.
- Returns `response.Response[T]` — the service decides status and error code.
- Maps domain errors with `errors.Is` → `NotFound` / `Conflict` / `Internal(err)`.
- Owns transactions and caching (read-through; invalidate on write; keys/TTLs from `meta/`).
- Maps ORM → `XxxRes` with a private `toXxxRes`.
- **Forbidden:** `fiber.Ctx`, `os.Getenv`, constructing its own dependencies, package-level state.

### 4. Repository (`repository/`)
- ctx first; driver call uses it (`db.WithContext(ctx)`, `coll.FindOne(ctx, ...)`).
- Translate driver errors to `domain.ErrNotFound` / `domain.ErrAlreadyExists`;
  Update/Delete affecting 0 rows → `domain.ErrNotFound`. Wrap the rest: `fmt.Errorf("find ticket %s: %w", id, err)`.
- **Forbidden:** business rules, logging, calling other repos/services/HTTP, string-built queries.

### 5. Contracts (`*_svc.go`)
- `XxxReq`: binding tags (`uri` / `query` / `json`) **and** `validate` tags; path fields `json:"-" uri:"id"`.
- `XxxRes`: explicit camelCase `json` tags; only fields the client needs.

### 6. Wiring (`app.go`) and Routes (`route.go`)
- `Run() error` — returns instead of exiting so defers run; `main` only maps error → exit code.
- Order: `config.Load()` (includes `Validate()`) → `logger.New` + `slog.SetDefault` → `signal.NotifyContext`
  → infra (`New`, then `defer Close()` right after) → repos → services → `route.New(route.Deps{...})`
  → `Listen` in a goroutine, `select` on listen error vs `ctx.Done()` → `Shutdown(timeout ctx)`.
- `route.Deps` holds `Config`, `Middleware` and every service; `route.New(deps)` reads no globals,
  so tests build it with `testDeps()`.
- Middleware order: `RequestID → AccessLog → Recovery → CORS → rate limit → groups`.
  `Recovery` turns a panic into a returned error (named return); `AccessLog` passes a non-nil
  error to `c.App().ErrorHandler(c, err)` before reading the status, so the logged status is correct.
- Docs route (`/docs`, Scalar + swaggo) registered only when `ServerMode != "prod"`.
- Templates for these files: [references/scaffold.md](references/scaffold.md).

## Cross-Cutting Rules

| Concern | Rule |
|---|---|
| Context | First param of every I/O func; handlers pass `c.Context()`; external calls `context.WithTimeout` + `defer cancel()` |
| Errors | Return, don't panic (bootstrap excepted — and still prefer returning from `Load`); wrap with `%w`; `errors.Is/As`; sentinels in `domain/` |
| Config | `os.Getenv` only via `envx` in `config/`; `Load() (*Config, error)`; fail fast in `Validate()`; only fields the product uses — no copy-pasted blocks |
| Logging | `slog` (`slog.InfoContext/ErrorContext`) configured once by `logger.New`; log at middleware boundary + business events; repos silent; never secrets/PII/response bodies |
| Concurrency | Every goroutine has a cancel path via ctx; `errgroup` for fan-out |
| Globals | No `sync.Once` singletons or package-level clients/config — `slog.SetDefault` is the one allowed global |
| Constants | Error codes, Locals keys, cache keys, TTLs in `meta/` — never string literals like `c.Locals("err")` |

## Testing Strategy
- **Service:** table-driven with `<resource>_repo_mock.go` + `redisdb.NewMemory()`; assert status, error code, `repo.AssertExpectations(t)`.
- **Route:** `New(testDeps()).app.Test(...)` — health, 404 envelope, panic → 500 envelope, docs hidden in prod, CORS.
- **Repository:** integration tests against docker-compose DB, build tag `integration`.
- `make vet test` green (`go test -race -count=1 ./...`); ≥ 80% on services.

## Security Checklist
1. No hardcoded secrets; `.env` and `*.pem` gitignored; `.env.example` committed with every key.
2. Validate every request in the service before the repo.
3. Parameterised queries only.
4. Write endpoints behind auth middleware; RBAC server-side.
5. 5xx never expose internal error text; logs never contain response payloads.
6. CORS origins explicit; no `*`; credentials off unless cookies are really used.
7. Container runs as non-root (see Dockerfile template).

## Smell → Fix

| Smell | Fix |
|---|---|
| SQL / driver call in a handler | Repo method; handler → service |
| Endpoint returns a non-envelope body (e.g. plain "Not Found") | Set `fiber.Config{ErrorHandler: response.ErrorHandler}` |
| `recover()` that swallows and returns nil | Named return `err = fmt.Errorf("panic: %v", r)` |
| `sync.Once` singleton / `NewXxx()` reading `config.GetConfig()` | Constructor with params; build once in `app.go` |
| util package imports `<module>/internal/config` | Take `Options`; caller passes `cfg.Redis...` |
| `context.Background()` inside redis/db helpers | Accept ctx from caller |
| Fiber v2 idioms (`*fiber.Ctx`, `c.UserContext()`, `ParamsParser`, `params:` tags) | v3: `fiber.Ctx`, `c.Context()`, `c.Bind().URI/Query/Body`, `uri:` tags |
| `response.Success(data, "msg")` logging the payload | Return the envelope; log events, not bodies |
| Aggregate `repository.Init()` with commented-out repos | Per-resource repo packages wired in `app.go` |
| Config fields for systems the product doesn't use | Delete; add when the integration lands |
| `err == redis.Nil` / `gorm.ErrRecordNotFound` in service | Repo returns `domain.ErrNotFound` |
| ORM struct returned as JSON | `XxxRes` + `toXxxRes` |

## Workflows

**New project** (bootstrap):
1. Confirm module name, binary name, goutil module path/version, DB (Postgres/Mongo/none), Redis yes/no.
2. `go mod init <module>`; `go get github.com/gofiber/fiber/v3 {{UTIL}}@<version>`.
3. Create every file in [references/scaffold.md](references/scaffold.md): main, app, route + test,
   middleware, health + swagger handlers, config, domain, meta, data/orm/doc.go, Makefile,
   Dockerfile, docker-compose (only the DB chosen), `.env.example`, `.gitignore`, `.golangci.yml`.
   Copy templates verbatim, replacing only the placeholders; drop the Redis lines if Redis is not used.
4. `make swag` → `go mod tidy` → `make fmt vet test build`; all green before reporting done.
5. Add the first resource with the steps below.

**New resource:** meta codes/keys + domain sentinels → orm model → repo (interface, impl, mock)
→ svc contract (Req/Res) → svc impl → svc tests → handler with swag annotations
→ add svc to `route.Deps`, construct in `app.go`, register in public/private group → `make swag fmt vet test`.

**Refactor / review:** survey against Smell → Fix; if the project has a consistent different
convention (sqlx, other folder names) keep the names and apply the rules. Fix in the order
sentinels → repo → contracts → service → handler → wiring → tests. Report smells fixed and
any left with the reason. Verify: `gofmt -l .`, `go vet ./...`, `go build ./...`, `go test -race ./...`.
